# Architecture Proposal Workflow

Use before material architecture, dependency, protocol, process-boundary
or backend changes.

1.  Describe current behavior and concrete problem.
2.  Present 2--3 viable options.
3.  Compare performance, complexity, compatibility, maintenance and
    migration risks.
4.  Recommend one option.
5.  Draft ADR with status `proposed`.
6.  Do not implement until user explicitly approves a specific option.
7.  After approval, update ADR and `DECISIONS.md`.
