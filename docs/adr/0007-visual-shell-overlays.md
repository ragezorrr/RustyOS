# ADR-0007: Visual Shell Overlays & Core UX Rendering (`RUSTYOS-012`)

- **Статус:** accepted
- **Дата:** 2026-11-12
- **Автор:** AI Agent + User

## Контекст

Согласно `ROADMAP.md` (Фаза 8 --- Core UX) и `DESIGN.md`:
- Текущее состояние оболочки (`TopBar`, `Dock`, `WorkspaceSwitcher`, `QuickSettings`) функционирует в `apps/rusty-shell` и передаётся через `rusty-ipc`, но до сих пор не имеет прямого визуального воплощения на экране.
- Пользователь должен видеть на экране:
  1. **TopBar** (высота 32px, темный полупрозрачный фон `#161023`, индикаторы активного и доступных рабочих столов `1..9`, индикатор активной раскладки, часы, статус батареи и сети).
  2. **Dock** (парящая нижняя плашка с радиусом скругления в стиле macOS, закреплённые приложения `Terminal`, `ES2 Gears`, карточки запущенных окон с точкой-индикатором фокуса).
  3. **Desktop Background** (аккуратный градиент `#0F0A19` -> `#161023`).
  4. **Интерактивность мышью**: клик по индикаторам воркспейсов `1..9` в TopBar плавно переключает рабочий стол; клик по иконкам в Dock переключает фокус/поднимает окно или запускает приложение.

## Рассмотренные варианты

### Вариант A: Нативный композитный рендеринг Overlay-элементов через Smithay custom render elements (Рекомендуемый)
- В `crates/rusty-compositor` добавляется модуль отрисовки элементов оболочки (`shell_render.rs`), генерирующий кастомные рендер-элементы (`PixelShaderElement` / `SolidColorRenderElement` с дизайн-токенами из `DESIGN.md`) и передающий их в `custom_elements` функции `render_output`.
- При кликах мыши по верхней полосе (Y < 32px) клик перехватывается как переключение рабочего стола или открытие настроек.
- При кликах по Dock переключается фокус окна.
- Резервируется рабочая область экрана для окон (`Rect::new(0, 32, width, height - 32 - 64)`), чтобы окна не перекрывали панель и док.

- **Плюсы:**
  - Нулевые внешние зависимости (использует уже готовый GlesRenderer Smithay).
  - Идеальный frame pacing, нулевые задержки отрисовки, мгновенный отклик на анимации рабочих столов и окон.
  - Мгновенная видимость интерфейса в окне Winit и DRM без необходимости подключения тяжелых сторонних GUI-фреймворков.
- **Минусы:**
  - Базовые векторные/прямоугольные элементы скругления и текст рендерятся через шейдерные примитивы.

### Вариант B: Подключить GTK4/Iced клиент через `wlr-layer-shell` прямо сейчас
- **Плюсы:** Готовые виджеты кнопок и шрифтов.
- **Минусы:** В песочнице нет скомпилированного GTK4-rs / Iced с сотнями транзитивных зависимостей (сломает offline-сборку).

## Решение

Выбрать **Вариант A**: реализовать аппаратный GLES-рендеринг оверлеев оболочки (TopBar, Dock, обои, индикаторы) в композиторе на базе дизайн-токенов из `DESIGN.md`, с эксклюзивными зонами для окон WM и кликабельностью рабочих столов и дока.

## Последствия
- При запуске `rusty-compositor` на экране сразу видна полноценная графическая DE: сверху TopBar со статусом и рабочими столами, снизу Dock с приложениями, между ними — область окон.
