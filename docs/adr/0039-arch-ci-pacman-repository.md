# ADR-0039: CI-конвейер публикации Arch Pacman репозитория и сквозное автообновление

- **Статус:** accepted
- **Дата:** 2026-11-16
- **Задача:** `RUSTYOS-079`
- **Связанные решения:** `D-047`, `D-046`, `D-045`, `D-044`, `ADR-0038`, `ADR-0037`, `ADR-0036`

## Контекст

После интеграции фонового сервиса проверки обновлений (`RUSTYOS-076`) и оконного приложения `rusty-updater` с Polkit-хелпером (`RUSTYOS-077`) обновление системы на хосте требовало либо ручной сборки через `makepkg -si`, либо запуска `rusty-updater` из клона с флагом `--pkgbuild-dir`, компилирующего Rust-код локально.
При каждом `git push` в `origin/main` CI валидировал сборку (`arch-packaging`), но собранный пакет никуда не публиковался, из-за чего штатные `checkupdates` и `pacman` не видели свежих коммитов RustyOS.

## Решение

1. **CI-конвейер публикации pacman-репозитория (`publish-arch-repo` в `.github/workflows/ci.yml`):**
   - Запускается строго после успешного завершения `check` (fmt, clippy, cargo test, smoke test) и `arch-packaging` при `push` в ветку `main`.
   - Внутри официального контейнера `archlinux:base-devel` от непривилегированного пользователя собирает пакет `rustyos-git` с динамическим `pkgver()` (на основе счетчика коммитов и short SHA).
   - Формирует официальную структуру Arch pacman-репозитория: `x86_64/rustyos.db.tar.zst`, `x86_64/rustyos.files.tar.zst`, симлинки `rustyos.db`/`rustyos.files` и собранный пакет `rustyos-git-*.pkg.tar.zst`.
   - Поддерживает GPG-подпись пакетов и базы данных: при наличии секрета `GPG_SIGNING_KEY` подписывает артефакты откреплённой подписью и экспортирует публичный ключ `rustyos.asc`; при отсутствии секрета создаёт стандартный репозиторий с диагностическим сообщением в лог.
   - Публикует артефакты сборки в `actions/upload-artifact@v4` и выгружает репозиторий в ветку `gh-pages` для раздачи через GitHub Pages (`https://ragezorrr.github.io/RustyOS/repo/$arch`).
   - Генерирует статическую страницу `index.html` с инструкцией по подключению.

2. **Интеграция с сервисами и интерфейсом RustyOS (`crates/rusty-services`, `apps/rusty-updater`):**
   - В `SystemReleaseSummary` добавлен признак `pacman_repo_configured`, проверяющий наличие секции `[rustyos]` в `/etc/pacman.conf` без запуска внешних процессов.
   - В `rusty-updater` отображается переход версий (`RustyOS <old> -> <new>`), статус готовности репозитория в подвале окна, а после завершения установки — явная рекомендация перезапустить сессию (`Log out / Restart session`) для вступления в силу нового кода композитора.

3. **Безопасность и невмешательство агента:**
   - Никакие изменения в системный `/etc/pacman.conf` и доверенную связку ключей `pacman-key` агентом автоматически не вносятся.
   - В `docs/GETTING_STARTED.md` документирована пошаговая процедура подключения репозитория пользователем с `sudo`.

## Последствия

- Любой запушенный в `main` коммит, прошедший тесты, автоматически становится доступным пользователю в виде готового бинарного пакета за секунды.
- Фоновый чекер композитора (`checkupdates`) автоматически подхватывает новые коммиты и зажигает индикатор обновления в TopBar.
- Нагрузка на локальный CPU хоста при обновлении устранена: компиляция происходит в облаке GitHub Actions.
