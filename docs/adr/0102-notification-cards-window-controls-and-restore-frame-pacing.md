# ADR-0102: Правосторонние кнопки окна SSD, исправление frame pacing развёртывания, аватары и стопки уведомлений (`RUSTYOS-173`)

- **Статус:** Accepted
- **Дата:** 2026-11-24
- **Решение:** `D-116`
- **Задача:** `RUSTYOS-173` (Эргономика окон, Notification Center и отзывчивость развёртывания)

## Контекст

В процессе практической эксплуатации и тестирования пользовательского опыта RustyOS было выявлено четыре ключевых проблемы в оконной подсистеме и центре уведомлений:

1. **Неинформативные заголовки и иконки уведомлений:**
   При поступлении сообщений через D-Bus Notifications (`org.freedesktop.Notifications`) от мессенджеров (например, Telegram Desktop) или веб-клиентов заголовок карточки принудительно форматировался с префиксом приложения (`"{app}: {summary}"`), а вместо фотографии отправителя отображалась общая системная иконка программы. Мессенджеры передают имя отправителя в поле `summary`, а аватар контакта — в D-Bus hints (`image-data`, `image-path`, `image_data`, `icon_data`, `app_icon`).

2. **Эргономика кнопок управления окном в Server-Side Decorations (SSD):**
   Кнопки управления окном («Свернуть», «Развернуть», «Закрыть») ранее были перенесены в левый угол заголовка SSD. Для традиционного десктопного взаимодействия с окнами SSD (браузеры, X11-клиенты, терминалы) привычным и эргономичным является расположение кнопок в правом верхнем углу окна в порядке `[Свернуть] [Развернуть] [Закрыть]`.

3. **Зависание окон при восстановлении из свёрнутого состояния (Unminimize Freeze):**
   При развёртывании ранее свёрнутого окна (через клик по иконке в Dock или через меню) окно восстанавливало геометрию, но не перерисовывалось и не реагировало на ввод до тех пор, пока пользователь не двигал окно мышью за заголовок. Причина заключалась в том, что X11 configure cache подавлял отправку повторных событий конфигурации, анимация развёртывания не генерировала непрерывное повреждение буфера (damage) для вызова Wayland frame callbacks в Smithay, а фокус указателя мыши не валидировался автоматически.

4. **Засорение Notification Center единичными карточками:**
   При получении пачки сообщений от одного приложения (например, серии сообщений из чата) вертикальный список центра уведомлений переполнялся повторяющимися карточками, затрудняя чтение и вытесняя виджеты погоды и напоминаний.

## Решение

Реализован комплекс согласованных улучшений в `crates/rusty-ui` и `crates/rusty-compositor`:

1. **Парсинг аватаров и имён отправителей из D-Bus Notifications:**
   - В `crates/rusty-compositor/src/state/mod.rs` введена структура `NotificationAvatar` (`width, height, rgba`), а в `CompositorNotification` добавлены поля `app_display_name` и `avatar`.
   - В `crates/rusty-compositor/src/dbus_notifications.rs` реализована функция `parse_notification_avatar`, извлекающая изображение контакта из структуры `image-data` (`(iiibiiay)` в формате `zbus`), `image-path` или `app_icon`.
   - Если `summary` не пусто, поле `title` уведомления устанавливается непосредственно из имени контакта/темы без паразитного префикса названия приложения, а само название приложения сохраняется в `app_display_name`.
   - В `crates/rusty-compositor/src/icons.rs` добавлен метод `avatar_element`, создающий круглую текстуру контакта с субпиксельным сглаживанием (antialiasing) и альфа-маской радиуса.
   - Во всплывающих тостах и карточках Notification Center аватар отображается в виде чёткой круглой миниатюры контакта вместо стандартного сквиркла приложения.

2. **Правостороннее размещение кнопок управления окном в SSD:**
   - В `crates/rusty-ui/src/traffic_lights.rs` и `geometry.rs` введён `TrafficLightPlacement` (`Left`, `Right`) и константа `TRAFFIC_LIGHT_MARGIN_RIGHT = 14`.
   - Метод `TrafficLightButtons::for_window(width, height)` автоматически рассчитывает геометрию для правого края окна с порядком кнопок: `Minimize` (`x = width - 72`), `Maximize` (`x = width - 50`), `Close` (`x = width - 28`).
   - В `crates/rusty-compositor/src/shell_render/ssd.rs` генерация декораций и хит-тестинг переведены на правостороннее размещение. Кнопка «Закрыть» располагается в крайнем правом углу, гарантируя безошибочное попадание курсором.
   - В CSD-приложениях с двухпанельным сайдбаром (например, `rusty-files`) сохранена поддержка левого расположения (`default_csd()`) для гармоничной интеграции со списком разделов.

3. **Гарантированный frame pacing и восстановление фокуса при развёртывании:**
   - В `crates/rusty-compositor/src/state/wm_windows.rs` при снятии флага минимизации (`unminimize`):
     - Из кэша X11-конфигураций принудительно удаляется запись окна (`last_x11_configure_state.remove(&win_id)`), гарантируя доставку свежего события перерисовки XWayland-клиентам.
     - Для нативных Wayland-окон вызывается `toplevel.send_configure()`.
     - Инициируется цикл отрисовки через `schedule_render_loop_for_output`, обеспечивая своевременную отправку frame callbacks со стороны Smithay.
     - По завершении пружинной анимации развёртывания вызывается `apply_pointer_position` с текущими координатами курсора, мгновенно передавая фокус мыши и клавиатуры развёрнутому окну без необходимости шевелить заголовок.

4. **Группировка карточек в стопки (Card Stacking) в Notification Center:**
   - В `crates/rusty-compositor/src/shell_render/notification_center.rs` реализована группировка уведомлений по идентификатору источника (`app_key` / `app_display_name`).
   - По умолчанию пачка уведомлений от одного приложения сворачивается в компактную стопку («стос»): отображается самое свежее верхнее уведомление, а под ним отрисовываются два выступающих нижних стеклянных слоя с уменьшенной прозрачностью и тенью, создавая физический эффект колоды карточек.
   - В заголовке карточки стопки отображается бейдж количества скрытых уведомлений (`+N`).
   - Клик по сложенной стопке плавно раскрывает (`ToggleStack`) все карточки группы, а повторный клик сворачивает их обратно.
   - В состояние композитора добавлено множество `expanded_notification_stacks: HashSet<String>`.

## Последствия и инварианты

- **0 новых зависимостей Cargo, 0 `unsafe`:** вся функциональность реализована на базе существующих структур `rusty-ui`, `rusty-compositor` и `zbus`.
- **Эргономика и предсказуемость:** восстановление из Dock работает мгновенно без зависания кадров; кнопки закрытия SSD-окон находятся на привычном месте; центр уведомлений остаётся чистым и организованным.
- **Инварианты дизайн-системы:** сохранена палитра Liquid Glass, динамические скругления и адаптивная прозрачность.
